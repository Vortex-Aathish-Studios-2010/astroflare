Verdict

The site is functionally sound and ready for review. The deterministic engine, the NASA evidence explorer and both AI features behave as designed on the live site. Testing uncovered a regression from the interface migration, a missing Content-Security-Policy and related headers, which is now fixed and verified live. The remaining caveats are about what could not be run on the development laptop (34 browser-simulation tests and a local container build), not about failures.

Honest scope. Tests were run by the person who built the system, on one Windows laptop, against the live free-tier service, in one browser engine (Chromium). That makes them useful but not independent. The unfinished list in section 8 matters as much as the passes.

Observations

  • Model fallback in action. Render's logs showed google/gemini-3.6-flash: 1 key(s) - cooldown before every request: the first model was in a free-tier cooldown after heavy testing, and the router fell through to gemini-3.5-flash-lite immediately. This is the designed behaviour and explains the roughly two-second answers. It also shows free-tier capacity is shared and can be exhausted.
  • Citation formats. Early on, one of three evidence explanations was withheld because the model wrote citations such as "PSI-99 row 2-5". The checker now accepts format variants that still name a real record or run. Afterward 13 of 13 API requests were accepted (3 plus 10), and one live interface request was withheld, so the checks remain cautious.
  • Safety wording. A question asking whether Saffire II proves a lunar habitat is safe produced no safety claim; the checker rejects unnegated safety words and the system prompt forbids them.
  • Reasons are visible. A withheld explanation now logs its reason code (never text or keys) in Render's logs.

Detail: the missing security headers

Found by: the "security headers" live check. Cause: the earlier Python site served the page itself and sent a strict Content-Security-Policy (script allowed only by hash), HSTS and framing protection. When the Vortex interface (a Node server) took over serving the page, it sent only X-Content-Type-Options and Referrer-Policy. Risk: an injected script would not have been blocked by the browser, and the page could be framed by another site. Fix: build.py now hashes the page's single inline script; the server sends a policy allowing exactly that script, plus X-Frame-Options, Permissions-Policy, Cross-Origin-Opener-Policy and HSTS over HTTPS. Verified: unit tests assert the hash equals the script's SHA-256; the live page runs with zero violations; plain assets such as the data set do not carry the page policy.
